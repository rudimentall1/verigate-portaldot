A proposal is not authority.

Inspect live PortalDot V3 state, connect an EVM wallet, and execute a signed Verigate payment authorization. The DApp never asks for private keys or seed phrases. It cannot create a Verigate authorization itself: each transfer must carry the bridge signer’s exact EIP-712 signature, pass simulation, and receive your explicit wallet approval.

What this dashboard demonstrates

On-chain guard
Current network, block, runtime code presence, balance and authority signer are read from the public RPC.
Execution constraints
The contract is designed to bind authorizations to chain, guard, recipient, exact amount, nonce, deadline and action ID.
Evidence boundary: a Verigate-authorized 0.1 POT payment was executed on public PortalDot V3. The receipt was re-queried from the configured RPC and its exact TransferExecuted event was matched. This prototype is not independently audited or a mainnet deployment; the EVM genesis hash pin is not configured and the RPC was not cross-checked with a second provider.
