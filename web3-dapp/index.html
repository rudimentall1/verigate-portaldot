Agent authorization infrastructure

A proposal is not authority.

Verigate keeps AI-proposed payments inside explicit authority. The policy decision happens off-chain; the bridge binds authorization to one exact action; the PortalDot guard enforces recipient and spending limits before funds move. This public page is read-only: it verifies live chain state and recorded evidence, but never broadcasts a payment.

01 / Verigate denial

BLOCK → NO AUTH

Verigate returns BLOCK for a disallowed recipient. The bridge refuses to create the EIP-712 execution authorization; the on-chain guard separately rejects unlisted recipients and over-cap transfers.

Evidence type: local Verigate integration + local Solidity tests; there is no recorded public-chain revert for these cases.
